# Premarket：盘前简报

用户在美股开盘前运行，想在几分钟内看清：

- 宏观上发生了什么，对哪些行业利多、对哪些行业利空。
- 每只股票最近发生了什么，今天和未来两周有什么事，现在的价格处在什么位置。
- 看多和看空各自最有力的理由是什么，哪些已经算进股价。

用户不熟悉技术分析，所有术语都要配大白话。

用户的习惯性错误是：财报"看起来非常好"就买入，结果市场的看法和他不一样。股价反映的是"相对预期"和"已计价程度"，不是财报的绝对好坏。所以多空两边都要认真判断是否已计价。

个股单日涨跌接近随机，公开消息在开盘前大多已反映在价格里。所以方向倾向只是参考，不给概率、不给目标价、不给买卖建议。

## 输入

用户调用时附带 1 个或多个 ticker，例如 `SPCX RKLB ASTS`。没有 ticker 就问用户要，不要猜。

## 数据规则

编造的日期和数字会直接误导交易，所以这几条是硬规则。

- 价格和技术指标只用行情脚本输出的数字，不自己估算，不凭记忆。
- 其他数据只用联网搜索和读取网页获取。财务数据优先用一手来源：公司财报新闻稿、电话会纪要、SEC 文件（10-Q、10-K、8-K、Form 4）；其次是主流财经媒体和分析师点评。
- 每条消息都要有来源链接和日期。每个关键数字都写明来源和日期，例如"营收 $35.1B，一致预期 $33.2B（公司新闻稿，2026-11-05）"。未来事件的日期尤其容易错，没有来源就不写具体日期。
- 来源之间数字冲突时，两个都列出并说明。
- 查不到就写"未找到"，不许估算。某个新闻类别搜过但没有结果，记入 `news_categories_empty`，让用户知道是查过了而不是漏了。
- 传闻可以收，但 `credibility` 必须标"传闻"，不能把传闻当成事实写进走势归因或多空理由。
- 无法联网时直接告诉用户做不了，不凭记忆出简报。
- 每次都从头查，不读以前的简报。

## 是否已计价

全篇的 `priced_in` 只用三个值：`已计价`（市场早已知道，已经算进股价）、`部分`、`未计价`。对照消息日期和脚本给出的当日涨跌来判断。

已经充分计价的利多不再是买入理由，已经充分计价的利空也不可怕。要如实标注，不要为了让某一边显得理由多而一律写"未计价"。

## 文件位置

- 脚本和模板在本 SKILL.md 所在目录下：`scripts/market_data.py`、`scripts/render_report.py`、`assets/template.html`。
- 输出目录是 `~/stock-bear/premarket/`，每次运行生成三个同名文件。`<stem>` 是简报日期 `YYYY-MM-DD`；当天已有文件时加序号（`-2`、`-3`），不覆盖。
  - `<stem>.market.json`：脚本拉取的行情
  - `<stem>.json`：你填写的简报数据
  - `<stem>.html`：渲染出的页面

## 流程

### 第 0 步：确定时点

运行 `TZ=America/New_York date` 得到美东时间。美股正常交易时段是美东 9:30 到 16:00。

- 开盘前：简报日期是今天。
- 盘中、盘后、周末或假日：照常出简报，简报日期是下一个交易日，并在 `session_note` 里写明当前时点，例如"盘后生成，'今天'指 11 月 12 日（周四）"。

### 第 1 步：拉行情

为每只股票选一个最贴近的板块或行业 ETF（例如航天股用 UFO 或 ITA，半导体用 SMH）。同一板块的股票共用一个。然后运行：

```bash
uv run --no-project <skill目录>/scripts/market_data.py \
  --out ~/stock-bear/premarket/<stem>.market.json \
  <TICKER...> <板块ETF...> ^GSPC ^IXIC
```

`^GSPC` 和 `^IXIC` 必须带上，宏观页要用。没有 `uv` 时改用 `python3`。

标准输出是摘要：

- 所有代码都有指标（均线、RSI、成交量倍数、支撑压力位、近 14 个交易日的最高价和最低价、缺口、52 周高低）和最新的盘前或盘后价 `extended`。
- 个股另有最近 14 个交易日的 K 线和近 6 个月的局部高低点 `swings`，用于走势对照和形态判断。
- 板块 ETF 和指数只另有最近 14 个交易日的逐日涨跌幅 `daily_change_pct`，用于判断个股某天的涨跌是否跟随板块或大盘。

完整的 6 个月 K 线在输出文件里，不需要你读。

某个代码返回 `error` 时：

- 是 ticker 写错就改正重跑。
- 确实拿不到时，这只股票仍然出简报，但在它的 `price_data_note` 里说明行情获取失败，并用搜索补上最新收盘价和涨跌幅。页面上它的图表和技术指标会显示为不可用。
- 行情文件里必须有这只股票的条目（哪怕是 error），否则渲染脚本会报错。

### 第 2 步：宏观

所有股票共用一份，只查一次。用户买的多是高估值成长股，"财报好却跌"里有相当一部分是被大盘或板块带下去的，和公司本身无关。宏观页的目的是把"环境的问题"和"公司的问题"分开。

- **大盘近况**（`summary`）：近两周 S&P 500 和 Nasdaq 的走势和主要归因。
- **货币政策与利率**（`rates`）：美联储最近的表态、市场对下次议息的预期、10 年期美债收益率的水平和方向。
- **宏观消息**（`news`）：过去 14 天影响市场的事件。
  - 收哪些：CPI、PCE、非农等经济数据，写明对比预期如何、市场怎么反应；还有选举、关税、财政、监管、战争与制裁等政策与地缘政治事件。影响整个市场的都收；只影响个别行业的，收与这些股票的板块有关的。
  - `market_impact`：对大盘是 `利多` / `利空` / `中性`。
  - `industries`：受影响的行业和各自的方向（`利多` / `利空`），最多 5 个；受影响的行业很多时只列影响最大的 5 个。同一条消息常常对一些行业利多、对另一些利空，比如关税，要分别标。没有明显的行业影响时留空数组。
  - 行业名用通用的中文名，例如半导体、软件、航天国防、银行、能源、医药、消费电子。
- **宏观日历**（`calendar`）：未来 14 天的 CPI、PCE、非农、议息会议、重要讲话等，`importance` 标 `高` / `中` / `低`。

### 第 3 步：逐只研究

每只股票依次做下面六件事，后面的依赖前面的结果。

#### 3.1 财报时点

查最近一次财报日期和下一次财报日期，对照今天的日期，确定 `earnings_mode`：

| 模式 | 条件 |
|---|---|
| `财报刚出` | 最近一次财报在约 10 天内 |
| `财报已过` | 最近一次财报在 10 天以前，且离下次财报超过约 2 周 |
| `财报前` | 离下次财报约 2 周以内 |

边界情况自行判断，`earnings_mode_basis` 写依据的日期。

#### 3.2 公司新闻

搜索引擎只返回热门标题，所以要按下面八类**逐类**搜，过去 14 个日历日和未来 14 个日历日都要覆盖：

| 类别（`category` 的取值） | 搜什么 |
|---|---|
| 运营事件与日程 | 发射、产品发布、投产、交付数据、试验结果，以及已公布的未来日程 |
| 合同与合作 | 新订单、合作协议、政府合同、收购与投资 |
| 官方披露 | SEC 8-K、新闻稿、财报日期、投资者大会 |
| 管理层言论 | 采访、社交媒体发言、大会演讲 |
| 分析师动作 | 评级、目标价变动及理由 |
| 资金面 | 内部人买卖、大股东持仓变化、解禁、增发、回购 |
| 监管与法律 | 审批、调查、诉讼、出口许可 |
| 竞争对手与上下游 | 对手的发布和财报、关键客户或供应商的消息 |

每条消息记录：

- `credibility`：`官方确认`（公司公告、SEC 文件、监管机构）、`媒体报道`（主流媒体的报道，公司未确认）、`传闻`（社交媒体、匿名消息、猜测）。
- `priced_in`：`已计价` / `部分` / `未计价`。

已发生的写进 `news`，未来的写进 `calendar`。昨天收盘后到现在的新消息另外放进 `overnight.items`。

#### 3.3 板块与行业

`sector.items` 的六项每项都要有结论：

1. **板块走势**：板块 ETF 近两周和近三个月相对大盘的表现；资金是在流入还是流出这个板块。
2. **同业财报**：同行业公司最近的财报和股价反应。同业的指引和评论往往预示这家公司的处境。
3. **行业事件**：影响整个行业的新闻，如关键客户的资本开支变化、行业价格战、新进入者、行业性监管。
4. **行业周期位置**：行业处在景气周期的什么阶段，市场是否在担心见顶。
5. **个股相对板块**：近期它是跑赢还是跑输板块。跟着板块一起跌说明是环境问题，单独跌说明是公司问题。
6. **利率敏感度**：这只股票属于哪一类。高估值、未盈利的成长股受利率影响远大于盈利稳定的公司。

`sector.driver` 用一两句话说明近期走势主要由公司自身、板块还是宏观驱动。

#### 3.4 财报专项

`earnings` 的每一项都必须给出结论；查不到的写"未找到"，不能省略该项。

`财报刚出` 模式做这 8 项：

1. **预期差**：实际值对比的是卖方一致预期，还是更高的买方预期（whisper number）？beat 的幅度和过去几个季度相比是否在缩小？
2. **指引**：下季和全年指引对比一致预期如何？上调幅度是否小于本季 beat 的幅度（这等于隐含后续减速）？有没有撤回或收窄指引？
3. **盈利质量**：beat 来自主业，还是一次性项目、税率、回购、会计调整？GAAP 与 Non-GAAP 的差距多大？经营现金流与净利润是否背离？应收账款和库存增速是否明显快于营收？
4. **关键指标**：市场真正盯的那个数是什么（如云业务增速、毛利率、用户数、订单积压、同店销售）？它是否不及预期，即使总营收和 EPS 都 beat？
5. **电话会**：管理层措辞是否比上季谨慎？分析师的追问集中在哪些问题上？有没有被回避的问题？
6. **已计价程度**：财报前 1 个月和 3 个月涨了多少？当前估值（forward P/E、EV/Sales 等）处于自身历史和同业的什么位置？期权隐含的财报波动幅度对比实际波动如何？
7. **仓位与情绪**：机构持仓是否拥挤？空头比例多少、趋势如何？财报后有无分析师降级或下调目标价，理由是什么？
8. **实际股价反应**：盘后和次日怎么走？媒体和分析师给出的归因是什么？如果股价下跌，这是最重要的线索，要把归因与前 7 项对上。

`财报已过` 模式：上面 8 项以最近一次财报为基础，再加一项 **财报后至今**：财报后发生了什么（降级、行业消息、宏观变化），当初的股价反应是否已被消化或逆转。

`财报前` 模式改做这 4 项：

1. **预期有多高**：一致预期和 whisper number 是多少？最近一个月预期是在上调还是下调？
2. **财报前涨幅与估值**：近期涨了多少，估值在什么位置？涨得越多、估值越高，好财报被"卖事实"的风险越大。
3. **历史财报日规律**：过去 4 到 8 次财报，beat 之后股价的实际涨跌如何？期权隐含波动多大？
4. **这次要过的坎**：市场最关注哪几个指标和指引？上季电话会留下了哪些悬念？

#### 3.5 Bull case 与 Bear case

两边结构相同，各自独立论证。页面把两边左右并排，方便对照。

- `top`：Bull 侧是市场此刻最看好的理由，Bear 侧是市场此刻最担心的问题。最多 3 条，按重要性排序。`level` 是 `公司` / `板块` / `宏观`。
- `points`：理由清单。`title` 用一句短语，页面会把它放进"影响 × 是否已计价"的矩阵里；细节写在 `evidence`。`impact` 是 `高` / `中` / `低`：Bull 侧指兑现后对股价的推动有多大，Bear 侧指后果有多严重。页面会按重要程度自动排序，不用自己排。
- `falsifiers`：证伪条件。出现什么具体、可观察的信号，说明这一边的主要理由不成立；`check` 写可检验的指标和时间点。

Bull 侧从这些方向找：预期差扩大或预期上修、指引上调、关键指标加速、尚未被定价的催化剂、估值相对自身历史和同业偏低、资金面（回购、内部人买入、空头回补）、行业顺风。

Bear 侧从这些方向找：3.4 发现的问题、板块和宏观的逆风。另外快速扫描下面 6 项通用空头清单，有实质内容的写进 `bear.general_risks`，没有的直接略过，不要凑数。每家公司都能列出二十条泛泛的风险，那是噪音。

- 竞争与护城河侵蚀
- 客户或供应商集中度
- 公司层面的监管与诉讼（针对这家公司的调查、诉讼、出口管制；行业性和宏观层面的已在前面覆盖）
- 资产负债表：债务到期、股权稀释、SBC
- 内部人减持与公司治理
- 会计红旗与做空机构报告

如果认真查完后某一边的理由确实很少或大多已计价，就如实这么写。喊狼来了或一味唱多都会让简报失去价值。

#### 3.6 今日分析

**走势与消息对照**（`price_action`）：把最近 14 个交易日分成几段明显的涨跌，每段写出对应的消息和归因，并标明主要驱动是 `公司`、`板块` 还是 `宏观`。个股跟着板块和大盘一起动时，驱动就不是公司消息。找不到对应消息的涨跌写"未找到明确原因"，不要硬配。

**技术分析**（`technical`）：定位是描述现状和关键价位，不是预测依据。

- 指标的数值和通用解释由页面模板直接从行情文件渲染，你不用重复写。
- `summary` 用两三句大白话概括：现在是涨势、跌势还是震荡；价格离最近的支撑位和压力位多远；成交量说明了什么。`support` 和 `resistance` 只收被触及至少两次的价位，离现价更近的参考位常常是 `recent_high` 和 `recent_low`（近 14 个交易日的最高价和最低价），两者都要看。先说人话，术语放在括号里。
- `patterns` 根据脚本给出的 `swings`（局部高低点）判断形态：W 底（双底）、M 顶（双顶）、头肩顶、头肩底、拱形顶、圆弧底、三角形收敛、上升或下降通道等。
  - 每个形态写 `status`（`明确` 或 `疑似`）、`basis`（引用具体的日期和价格）、`plain`（一句大白话说明这个形态是什么、通常意味着什么）。
  - 形态判断很主观。看不出来就让 `patterns` 为空数组，页面会显示"无明显形态"。不要硬套。
  - 上市时间短、数据不足的股票（如不满 200 天），在 `summary` 里说明哪些指标因此缺失。

**情景分析**（`scenarios`）：今天出现什么情况偏利好、什么情况偏利空，每条配一个可以盯的具体信号（价位、数据公布时间、消息）。

**是否不宜动手**（`caution`）：今天或明天有会引发大幅波动且方向不明的事件时标记，例如财报当天、CPI 或议息公布前、关键发射或审批结果出炉前。

**方向倾向**（`tendency`）：`偏多` / `偏空` / `无倾向`，附两三句理由。

- 综合多空对照来判断：哪一边的未计价理由更有力。
- 没有明确依据时必须写"无倾向"，这是合法且常见的答案。
- 理由要区分哪些已经反映在盘前价格里。盘前已经大涨时写"偏多"只是在复述行情，要在理由里说明这一点。
- 不给概率、不给目标价。

### 第 5 步：渲染并打开

```bash
uv run --no-project <skill目录>/scripts/render_report.py \
  ~/stock-bear/premarket/<stem>.json \
  --market ~/stock-bear/premarket/<stem>.market.json
open ~/stock-bear/premarket/<stem>.html
```

渲染脚本会校验 JSON，包括枚举值、条数上限和固定项；报错时按提示改正后重跑。不要自己写 HTML，也不要改模板：页面样式固定是为了每次看起来一致。

页面左侧是侧边栏：第一项是宏观页，下面每只股票一页。个股页依次是今日分析、多空对照（Bull case 和 Bear case 左右并排，下面是财报专项和板块与行业）、新闻与日历、来源。侧边栏底部的按钮切换红绿配色，默认绿涨红跌。

### 第 6 步：在对话里给摘要

页面是主输出，对话里只写简短摘要，不要重复全文：

- 宏观一行：最重要的一两条宏观消息，以及它利多和利空的行业。
- 每只股票一行：方向倾向和一句理由；多空各最重要的一条；标了"不宜动手"的要写出来。
- HTML 文件的完整路径。
- 一句提醒：方向倾向和多空判断未经验证，仅供参考。

用中文写，ticker、术语和来源保留英文原文。
